# 3D Viewer and Flight Replay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every run with CAD output gets a standalone offline `viewer.html` (Shape, X-ray with CG, SITL flight replay) that the web form shows in a new **3D** tab.

**Architecture:** The CAD stage tessellates the `PackingResult` solids into `viewer_model.json`; the SITL bridge logs heading and north/east position in its truth trace and the report records which attempt to replay; `compile_report` builds `viewer.html` by inlining vendored Three.js, the page script and a JSON data block; the Streamlit app embeds that file.

**Tech Stack:** Python 3.12, build123d 0.13 (tessellation), JSBSim/ArduPilot SITL (Docker only), Three.js 0.170.0 (vendored), Streamlit `components.v1.html`, pytest + Streamlit `AppTest`.

**Spec:** `docs/superpowers/specs/2026-11-16-3d-viewer-design.md`

## Global Constraints

- Python with type hints on all functions and variables; `pathlib.Path`; f-strings; functions < 50 lines; files < 800 lines; no magic numbers (named `Final` constants); immutability (frozen dataclasses / new objects).
- No new Python dependencies. Three.js **0.170.0** vendored under `src/viewer/vendor/` with its MIT `LICENSE`.
- The page loads nothing from the network: no `http://` or `https://` in any `src=`, `href=` or import.
- All run data reaches the page only through one `<script type="application/json" id="viewer-data">` block, serialised with `json.dumps` and with every `</` written as `<\/`. Page code inserts data into the DOM with `textContent` only, never `innerHTML`.
- CAD frame: SI metres, **x aft from the nose, y right, z up** (`src/tools/aero_cad/layout.py:1`).
- Trace keys added: `heading_deg`, `north_m`, `east_m`. Existing trace keys unchanged.
- `sitl_report.json` gains `"replay_attempt": <int>` = the attempt number of `flown[-1]`.
- Output files in the run folder: `viewer_model.json`, `viewer.html`. `viewer.html` ≤ 8 MB.
- A mesh-export or viewer-build failure is a run warning, never a failed run, never silent (log it).
- Commits: conventional commits ending with
  `Co-Authored-By: WOZCODE <contact@withwoz.com>` and
  `Claude-Session: https://claude.ai/code/session_01RJfaxdHYf7KowUaPPCoa8G`.
- Host test command: `.venv/bin/python -m pytest -q -p no:cacheprovider` (JSBSim/OpenVSP/SITL tests skip on the host). Docker: `docker run --rm -v "$PWD":/app -w /app isr-forge:latest python -m pytest -q -p no:cacheprovider`.

## Review Focus

1. A run made before this feature (trace without `heading_deg`/`north_m`/`east_m`) → the replay plays altitude, roll and pitch in place with heading fixed and shows a note; nothing throws. (Task 3 test + browser check.)
2. A run with CAD but no SITL (SITL unchecked, or SITL error) → Shape and X-ray work, no replay panel, no error. (Task 3 test.)
3. A component name containing `</script>`, quotes or `<img onerror=…>` → appears as text, never as markup or script. (Task 3 test.)
4. Mesh export raises (e.g. a solid that will not tessellate) → the run completes, `cad.viewer_model_path` is `None`, and a warning names the failure. (Task 2 test.)
5. The app shows a run whose `out_dir` is `None` or whose folder lacks `viewer.html` → an info message, not an exception. (Task 5 test.)

  - `export_viewer_model(result: PackingResult, out_dir: Path) -> Optional[Path]` — wraps the two above; on any exception logs with `logger.exception` and returns `None`.
  - `VIEWER_MODEL_FILE: Final = "viewer_model.json"`; tolerances `LINEAR_TOLERANCE_M`, `ANGULAR_TOLERANCE_RAD` (builder picks values; Task 6 checks the 8 MB limit on real designs).

    part = mesh_export.tessellate(build123d.Solid.make_box(1.0, 0.5, 0.25), "battery", "component", 2.0)
